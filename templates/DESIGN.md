## 1. Design Brief

### 目的

使用者在準備晚餐時發現缺少食材，現在必須搜尋資料、比較替代方案，容易分心並延後開飯。本設計要讓會下廚、且有時間壓力的使用者，在同一個單頁工具內輸入原菜色、缺少食材與家中現有食材，快速選定一個能維持原菜色與相近味道的替代方案。

### 使用者與情境

| 項目 | 說明 |
| --- | --- |
| 主要使用者 | 25–60 歲、平常會自己下廚、使用手機搜尋時容易分心的人。 |
| 使用情境 | 晚餐前在廚房，以手機為主操作；發現缺少食材後希望盡快開始料理。 |
| 已知資訊 | 原本想做的菜、缺少的一種食材、家中可使用的相關食材。 |
| 顧慮 | 不想為了查資料跳到其他網站，也不想被迫重想另一道晚餐。 |
| 核心目標 | 在五分鐘內選擇一個可行替代方案，繼續原本料理。 |

### 設計限制

| 類型 | 決策 | 來源 |
| --- | --- | --- |
| 範圍 | 只支援「缺少一種食材」的晚餐替代決策；不做採買、料理教學、完全不同菜單推薦與複雜個人化。 | PRD §4 |
| 步驟 | 從開啟到選擇方案不超過八個使用者操作步驟。 | SRS NFR-03 |
| 裝置 | mobile-first；同時在平板與桌面瀏覽器可用。 | 設計決策 |
| 資料 | 不要求登入或先建立個人食材資料；本機儲存由 SAD 的架構處理。 | SRS NFR-02、SAD |

## 2. UX：流程與 IA

### UX 原則

| 原則 | 設計落點 |
| --- | --- |
| 先完成任務 | 首屏直接呈現三個輸入欄位與主要 CTA，不放產品功能清單或複雜導覽。 |
| 先給結論 | 結果卡先顯示「用什麼替代」與「用多少」，再顯示做法與味道／口感差異。 |
| 減少重填 | 驗證或服務失敗時保留輸入；使用者可返回修改條件。 |
| 清楚說明限制 | 找不到可接受方案時說明原因，並提供修改食材或改換菜色的明確行動。 |

### 核心流程

```text
開啟工具 → 輸入原菜色 → 輸入缺少食材 → 輸入家中食材
          → 查看替代建議 → 選擇一個方案 → 開始料理
```

| 步驟 | 使用者行為 | 畫面回應 | 需求 |
| --- | --- | --- | --- |
| 1 | 輸入原本想做的菜色 | 顯示已填狀態 | FR-01 |
| 2 | 輸入缺少的一項食材 | 顯示已填狀態 | FR-02 |
| 3 | 輸入家中可用食材 | 提示以逗號分隔，可留空但應提醒結果可能受限 | FR-03 |
| 4 | 點擊「查看替代建議」 | 按鈕進入 loading，避免重複送出 | FR-04、NFR-01 |
| 5 | 查看方案 | 每張卡顯示替代食材、用量、做法修改與差異 | FR-04～FR-07 |
| 6 | 選擇方案 | 顯示已選方案與「可以開始料理了」確認 | FR-08 |

### 例外與空狀態

| 情境 | 顯示內容 | 使用者行動 | 需求 |
| --- | --- | --- | --- |
| 必填欄位空白 | 「請輸入原本想做的菜色」或「請輸入缺少的食材」，焦點移至第一個錯誤欄位。 | 修正後重送。 | FR-01、FR-02 |
| 家中食材未填 | 欄位旁提示「可留空，但建議會較不精準」。 | 繼續送出或補填。 | FR-03、NFR-02 |
| 處理中 | 「正在找可用的替代方式…」與不具誤導性的 loading indicator。 | 等待；保留輸入。 | NFR-01 |
| 找不到可接受方案 | 「目前找不到能維持這道菜的合適替代方式。」 | 「修改食材」或「換一道菜」。 | NFR-04 |
| 外部服務失敗 | 「暫時無法產生建議，你填寫的內容已保留。」 | 「再試一次」或「修改食材」。 | SAD 圖 4 |

### Information Architecture

```text
晚餐選擇器（單頁）
├── 輸入區：菜色、缺少食材、家中食材、送出
├── 回饋區：欄位錯誤、loading、服務錯誤
└── 結果區：替代方案卡、已選確認、無結果引導
```

不做帳號、歷史頁、設定頁或主要導覽；結果在同一頁輸入區下方出現，使用者可直接回到輸入區修改。

## 3. Wireframe

```text
┌──────────────────────────────────────┐
│ 晚餐選擇器                            │
│ 缺一樣食材，也能繼續做原本的菜。      │
│                                      │
│ 原本想做什麼？ *                     │
│ [例如：番茄炒蛋________________]     │
│ 缺少哪一樣食材？ *                   │
│ [例如：番茄____________________]     │
│ 家中還有哪些相關食材？                │
│ [例如：雞蛋、洋蔥、番茄醬_______]     │
│                                      │
│ [          查看替代建議          ]    │
│                                      │
│ 結果區：送出前不顯示；送出後顯示       │
│ [方案卡：替代物／用量／做法／差異／選] │
└──────────────────────────────────────┘
```

結果卡的資訊順序固定為：替代食材 → 用量 → 做法修改 → 味道／口感差異 → 選擇此方案。

## 4. UI Specification

### 視覺方向

整體為溫暖、清楚、低壓的廚房小工具：留白充足、單一主行動、以文字資訊為主。不使用食材照片或裝飾性插畫；僅可使用通用線性圖示輔助狀態。

### Tokens

| 類別 | Token | 值 |
| --- | --- | --- |
| Color | `color.background` | `#FFF9F3` |
| Color | `color.surface` | `#FFFFFF` |
| Color | `color.primary` | `#B45309` |
| Color | `color.primary-hover` | `#92400E` |
| Color | `color.text.primary` | `#1F2937` |
| Color | `color.text.muted` | `#6B7280` |
| Color | `color.border` | `#E5E7EB` |
| Color | `color.success` | `#166534` |
| Color | `color.error` | `#B91C1C` |
| Typography | `font.family` | `system-ui, -apple-system, "Noto Sans TC", sans-serif` |
| Typography | `font.heading` | 28px / 36px / 700；mobile 24px / 32px / 700 |
| Typography | `font.body` | 16px / 24px / 400 |
| Typography | `font.caption` | 14px / 20px / 400 |
| Spacing | `space.scale` | 4, 8, 12, 16, 24, 32px |
| Radius | `radius.md` | 12px |
| Elevation | `shadow.surface` | `0 1px 2px rgba(31,41,55,.08)` |

### 元件規格

| 元件 | 規格 | 必備狀態 |
| --- | --- | --- |
| Button | 高度至少 48px；primary 用於「查看替代建議」；secondary 用於修改或重試。 | default、hover、focus-visible、disabled、loading |
| Input / Textarea | 可見 label；菜色與缺少食材為必填；家中食材可用逗號分隔。placeholder 只提供例子。 | default、filled、focus、error、disabled |
| Result card | 白色表面、12px 圓角；一張卡是一個方案；標題顯示替代物與用量。 | default、selected、unavailable |
| Inline feedback | 顯示在相關欄位或結果區附近，不用 toast 取代關鍵錯誤。 | loading、error、empty、success |

### Responsive

| 範圍 | 規則 |
| --- | --- |
| Mobile < 768px | 單欄，頁面左右 16px，CTA 全寬；結果卡直向排列。 |
| Tablet 768–1023px | 單欄，內容最大 640px；表單欄位仍維持直向，避免增加操作負擔。 |
| Desktop ≥ 1024px | 內容最大 960px；輸入區與結果區可各占一欄，但表單欄位維持清楚的垂直閱讀順序。 |

## 5. Interaction、狀態與錯誤

| 元件 | 觸發 | 行為與回饋 | 需求 |
| --- | --- | --- | --- |
| 查看替代建議 | 必填資料有效後點擊 | 送出目前輸入，按鈕顯示 loading 且不可重複點擊；成功後結果區捲入視野。 | FR-04、NFR-01 |
| 必填欄位 | 空白送出 | 不送出；顯示具體錯誤並聚焦第一個錯誤欄位。 | FR-01、FR-02 |
| 方案卡 | 點擊「選擇這個方案」 | 卡片顯示 selected，其他卡維持可選；顯示確認文案。 | FR-08 |
| 修改食材 | 結果不適合或無結果 | 保留現有輸入，捲回輸入區並聚焦相關欄位。 | NFR-04 |
| 再試一次 | 服務失敗 | 保留輸入並重新提交。 | SAD 圖 4 |

所有互動元件均可鍵盤操作、有清楚 focus 樣式；錯誤、成功與選取狀態都要同時用文字與顏色表達；可點擊目標至少 44 × 44 CSS px。

## 6. Technical Handoff

### 資產

本 POC 不需要 logo、照片或自訂字型。可使用系統字型與 CSS；若使用圖示，採用專案既有的開源通用圖示並提供可辨識名稱。

### 需求追溯

| 需求 | UI 落點 | 驗收 |
| --- | --- | --- |
| FR-01～FR-03 | 三個輸入欄位與 inline validation | 可提供菜色、缺少食材、家中食材。 |
| FR-04 | loading 後的替代方案結果區 | 顯示至少一個可行方案或明確無結果。 |
| FR-05～FR-07 | 每張結果卡的用量、做法修改與差異欄位 | 三項資訊皆可讀取。 |
| FR-08 | 結果卡的選擇按鈕與確認區 | 能選中一個方案並看見確認。 |
| NFR-01 | 快速單頁流程與 loading | 人工計時完成決策不超過五分鐘。 |
| NFR-02 | 不要求登入、設定或食材資料庫 | 首次開啟可直接輸入。 |
| NFR-03 | 單頁六步流程 | 操作不超過八步。 |
| NFR-04 | 無結果畫面 | 可修改輸入或換一道菜。 |

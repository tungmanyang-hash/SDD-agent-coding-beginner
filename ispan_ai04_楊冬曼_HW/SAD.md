## 圖 2：資料模型　**最重要的一張**

[你要存哪些東西，每個東西有哪些欄位。]

```text
[晚餐決策]（一次晚餐替代決策）
├─ dish              原本想做的菜色
├─ missingIngredient 缺少的食材
├─ availableIngredients 家中可使用的食材
├─ alternatives      替代方案
└─ selectedAlternative 使用者選擇的方案
```

> ⚠️ **每個欄位都要能回答「少了它會怎樣」。** 答不出來的欄位，刪掉。
>
> 反過來也要問一次：**有沒有哪個欄位是你之後一定會想加，但現在漏掉的？** 那才是真正會咬你的。

## 不可逆的決定

[哪些決定之後很難改？列出來，並寫下「如果將來要改，成本是什麼」。]

| 決定            | 為什麼難改             | 將來要改的成本                 |
| --------------- | ---------------------- | ------------------------------ |
| 保存／當次資料  | 會影響整個資料架構     | 增加資料庫、資料模型、儲存邏輯 |
| 是否需要登入    | 會影響使用者與資料關聯 | 增加帳號、權限、登入流程       |
| 是否跨裝置同步  | 決定資料放本機還是雲端 | 改變儲存架構                   |
| AI 邏輯放在哪裡 | 會影響核心判斷方式     | 重寫 Prompt／後端邏輯          |

## 風險表

[3–5 條。]

| 風險                  | 什麼時候會炸       | 我打算怎麼辦     |
| --------------------- | ------------------ | ---------------- |
| AI 給出不合理替代方案 | 實際料理時         | POC 實測替代結果 |
| AI 回覆太慢           | 使用者等待超過預期 | 實測 NFR-01      |
| 想跨裝置使用          | 換手機後資料消失   | 先決定本機／雲端 |
| 替代方案太多或太少    | 實際使用時難以選擇 | POC 後決定數量   |

> 「我打算怎麼辦」寫「POC 階段接受這個風險」是完全合格的答案 ——
> 前提是你**知道**自己在接受它。
